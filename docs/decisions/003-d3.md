# ADR-003: Use D3.js for geography and data-driven visuals

**Status**: Accepted

## Context

obfina's central visualization is a world map (see [ADR-007](007-2d-map-over-globe.md)), which needs a geographic projection, TopoJSON boundary handling, and data-driven scales for marker size, color, and opacity. It will also grow time-series charts (bandwidth over time) and histograms (relay distribution by AS). These require precise data-to-pixel mapping that general-purpose chart libraries handle less flexibly.

Candidates evaluated: D3.js, Chart.js, Recharts, Observable Plot.

## Decision

Use D3.js directly — `d3-geo` for the map projection and paths, `d3-zoom` for pan/zoom, and `d3-scale` for the marker encodings — plus the same primitives for future charts.

## Consequences

**Benefits:**

- D3 operates on the DOM directly rather than through a virtual layer, which matches Svelte's compilation model. A Svelte component can own an `<svg>` element and bind D3 scales/projections reactively without the DOM conflicts that occur in React.
- D3's geographic projection system (`d3-geo`) is the standard for map projections and integrates with the `world-atlas` TopoJSON, which obfina uses for the base map.
- D3 scales (`scaleSqrt`, `scaleLinear`) and `d3-zoom` are composable primitives — we import only the modules we use, keeping the bundle small.

**Tradeoffs:**

- D3's API surface is large and its documentation is dense. Contributor onboarding for chart-related code takes more time than with a higher-level library like Chart.js.
- D3 transitions and Svelte transitions can conflict if both attempt to animate the same element. The convention in obfina is that D3 owns SVG elements entirely and Svelte handles HTML-layer transitions only.
- Observable Plot would have been a simpler API for most of the chart types obfina needs, but its geographic support is weaker than D3's.
